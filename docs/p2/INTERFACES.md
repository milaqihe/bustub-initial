## 页面约定

- 当前类为 `BPlusTreePage`、`BPlusTreeInternalPage`、`BPlusTreeLeafPage`，均使用 BufferPoolManager 取得的 Page 数据区。节点不是单独 `new` 出来的树对象。
- 内部页第 0 个 key 无效，但第 0 个 child page_id 有效；内部页 size 的计数含义必须与定位、分裂、借元素和合并一致。
- 叶子页保存 `KeyType → RID`，通过 `next_page_id_` 形成单向链；不要按教程泛化图擅自改成另一种布局。
- 内部页和叶子页的 `max_size` 可以不同。1/2/3 需确定各自的满页、最小占用、根页例外，以及分裂/合并前后的 size，写入本页后统一使用。
- 页面搬移后，负责该次树操作的 2/3 号维护被搬移孩子的 parent_page_id；辅助函数若承担此操作，需明确标注。
- 页内辅助方法与树层操作分开：页内方法操作布局与键值，树层负责 Fetch/New、pin、dirty 与页面锁。

## 树与根页

- 保留现有 `GetValue`、`Insert`、`Remove`、`Begin`、`End` 签名及 transaction 参数。
- 只支持唯一键：重复 Insert 返回 false，不能像 P1 哈希表那样覆盖成另一条记录。
- 2 号负责首次建树、分裂升根；3 号负责删空和根收缩。root_page_id 变化时调用现有 `UpdateRootPageId`，保证 header 页中的记录同步。
- comparator 的返回值决定键的相对顺序，不把 GenericKey 当成整数直接比较。
- 每次 Fetch/New 取得的 pin 必须有对应释放；修改过的页面在 Unpin 时保留 dirty。是否持锁、由谁解锁和释放 pin 要在辅助方法注释中写清。

## 迭代器与并发

- `Begin(key)` 定位第一个不小于 key 的键；测试包含 key 不存在、位于两页之间、大于最大值和空树的情况。
- IsEnd 表示越过最后一个有效元素的结束态，不是“正好指向最后一项”。`operator*`、`operator++`、相等/不等比较围绕同一结束态定义。
- 4 号定义迭代器拥有的页面 pin/读锁、跨页释放和析构行为；复制/移动语义也要明确，避免重复释放。
- 5 号在 `Page` 上获取读写锁；transaction 的 `GetPageSet` / `AddIntoPageSet` 跟踪路径页，`GetDeletedPageSet` / `AddIntoDeletedPageSet` 跟踪待删除页。
- 先获取子页锁，再按安全条件释放祖先；修改根页需独立协调根页入口保护。页面先 unlatch 再 unpin。
- 5 号和 4 号共同确定迭代器扫描与兄弟节点合并的锁顺序，按教程处理叶链横向访问，验证不发生循环等待。
