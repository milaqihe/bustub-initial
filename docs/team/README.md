# 五人任务与集成顺序

采用小组分工图中的“3 个模块负责人 + 1 个集成负责人 + 1 个质量负责人”。下面是团队执行约定；课程截止时间、报告格式和评分细则仍按老师通知安排。

## 文件归属

| 编号 | 负责写入的文件 | 对接对象 | 必须交出的成果 |
| --- | --- | --- | --- |
| [1 号](member-01.md) | 根目录及 `test/` 的 CMake 配置、构建与接口文档、必要的 CI 配置、`reports/p1/integration.md` | 全组，主要协调 4、5 号 | 可复现构建、冻结的接口约定、合并记录、最终六文件提交包 |
| [2 号](member-02.md) | 哈希表 `.h/.cpp` 与原有哈希表测试文件 | 4、5 号 | 可扩展哈希表实现、基础测试、拆桶说明 |
| [3 号](member-03.md) | LRU-K `.h/.cpp` 与原有 LRU-K 测试文件 | 4、5 号 | 通用 K 的置换器、基础测试、可手算淘汰序列 |
| [4 号](member-04.md) | BufferPoolManagerInstance `.h/.cpp` 与原有缓冲池测试文件 | 2、3、5 号 | 六个页面操作、状态维护、脏页回写与基础集成测试 |
| [5 号](member-05.md) | `test/p1_quality/`、`reports/p1/` 中除 `integration.md` 外的报告 | 2、3、4 号报告缺陷，1 号确认验收 | 独立边界/并发/压力测试、ASan/TSan 记录、流程图、实验报告与答辩提纲 |

2、3、4 号可在自己的现有测试文件中追加基础用例，保留原有断言。5 号把新增测试放进独立目录，避免多人同时修改同一测试文件。若发现他人模块问题，提交最小复现，由该模块负责人修复；跨模块变更在同一个 PR 中明确列出涉及人员。

## 开工与阶段安排

### 阶段 A 接口与环境

- 1 号确认所有人能克隆、推送个人分支；记录统一编译器、CMake、构建类型和 Sanitizer。
- 2、3、4 号一起阅读[接口约定](../INTERFACES.md)，核对现有头文件签名。公开签名保持一致，内部成员和私有辅助函数由模块负责人设计。
- 4 号先画出 `NewPage`、`FetchPage` 的状态流程；5 号先补充测试计划与报告框架。
- 每人先提交一个可审阅的小改动或开发说明 PR，确认协作流程可用，不能用空提交充当功能完成。

### 阶段 B 模块开发

- 2、3 号可以并行实现和运行各自模块测试。
- 4 号按固定接口实现缓冲池，阅读现有 `Page`、`DiskManager` 和公开调用包装层。可在自己的分支编译，但最终功能测试依赖 2、3 号真实实现。
- 5 号独立编写边界用例、手算参考结果和并发测试方案；模块尚未完成时，记录“待依赖”而不是修改断言让测试通过。

### 阶段 C 合并与联调

1. 2 号哈希表基础测试通过，1 号审阅后合并。
2. 3 号 LRU-K 基础测试通过，1 号审阅后合并。2、3 号的先后可互换。
3. 4 号把最新 `origin/main` 合入个人分支，再跑缓冲池完整测试，修复后提交 PR。
4. 5 号基于三个模块齐备的版本运行补充测试、ASan 和 TSan，发现缺陷交对应负责人修复。
5. 1 号合并修复与补充测试后，在最终 `main` 重跑 P1 三组测试；5 号针对最终提交号更新验收记录。

不要让 4 号复制 2、3 号尚未合并的整个文件进自己的提交。确需提前联调时，在临时集成分支合并两人的分支，保持各模块提交与归属清楚。

### 阶段 D 提交与汇报

- 1 号：打包六个课程文件，核对压缩包路径与课程要求，记录最终提交号与包名。
- 2 号：说明目录扩容、局部/全局深度、兄弟指针和重复键处理。
- 3 号：说明不足 K 次优先淘汰、倒数第 K 次访问时间与可淘汰计数。
- 4 号：说明缓存命中/缺失、pin/unpin、dirty 写回和帧复用。
- 5 号：汇总实验报告、流程图和实际测试结果，逐人准备答辩问答。

## 合并条件

| PR 类型 | 合并前要求 |
| --- | --- |
| 2 号模块 PR | 哈希表完整现有测试与新增基础用例通过，4 号能按既有签名调用 |
| 3 号模块 PR | LRU-K 完整现有测试与新增基础用例通过，覆盖 K=1/2/3 与状态计数 |
| 4 号模块 PR | 同步 2、3 号已合并实现后，缓冲池完整测试通过；无误删历史、脏页丢失和死锁 |
| 5 号测试 PR | 用例有独立预期，能稳定复现问题或验证要求；报告注明被测提交号与环境 |
| 最终验收 | 最终 main 的三组测试、约定补充测试与检查通过；失败/受阻事项有实际处理结论 |

`.github/workflows/cmake.yml` 已为五人协作配置 P1 工作流：监听 `main`、`team/**` 推送和面向 `main` 的 PR。工作流只运行 P1 及约定补充测试，失败会保留诊断输出，全部检查成功后才生成提交包。1 号分支推送后，以实际 Actions 结果为准；当前本地检查与待合入事项见[集成记录](../../reports/p1/integration.md)。
